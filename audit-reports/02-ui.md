# UI issues

Static review of Mac SwiftUI, Windows WinForms, the shared React dashboard, and compact tray/menu-bar chrome. The apps were not launched in this environment. Layout, contrast, VoiceOver, and Narrator claims that need a running UI are labeled as hypotheses.

Related verification notes already in-repo: `docs/UI-VERIFICATION.md`, `docs/DESIGN.md`, `docs/MAC.md` Dashboard text size, `docs/WINDOWS.md` Native main-window preview.

## Three shells, three visual systems

| Shell | Stack | Theme | Type | Charts |
| --- | --- | --- | --- | --- |
| Mac main window | SwiftUI `NativeDashboard` | `@AppStorage("observatoryAppearance")` light/dark, Inter Tight via `ObservatoryTheme.registerFont()` | `observatoryTextScale` 75% to 200% | Swift Charts |
| Mac menu-bar panel | SwiftUI `ObservatoryPanel` | Forced `.preferredColorScheme(.dark)` (`Panel.swift` lines 103, `main.swift` line 199) | System fonts, no dashboard zoom (`docs/MAC.md` line 19) | Compact allowance rings |
| Windows main window | WinForms `NativeDashboard` | Fixed dark `#1E1E20` / `#272729` (`NativeDashboard.cs` lines 27 to 29) | Segoe UI 10 / 22. No zoom. | Custom GDI+ `OnPaint` graphs |
| Windows tray popup | Borderless `UsagePopup` | Dark, sized to content | Mixed Segoe sizes | Custom quota/activity graphs |
| Shared web / demo / legacy | React in `app/page.tsx` | `localStorage` `usage-theme`, default dark | CSS in `observatory.css` | Inline SVG. `recharts` unused by these views. |

Hypothesis: a user who opens the Mac dashboard in light mode, then clicks the menu-bar icon, sees a dark compact panel with different type. That is documented as zoom-excluded. It is not documented as appearance-excluded.

Windows native never follows system light mode. The web dashboard and Mac native do. Hypothesis: Windows light-mode users get a permanently dark native window while the `--legacy-dashboard` web theme can still be light.

## Information hierarchy

### Default landing is Allowances, not screen time

README leads with Screen time. GUIDE says Activity opens in Day view. All three UIs select Allowances first.

Mac `NativeDashboardSelection.section` defaults to `"allowances"`. Windows `sections.SelectedIndex = 0` is Allowances. Web `useState('allowances')`. Fresh launch on Mac calls `openDashboard("allowances")` (`native/main.swift` lines 84 to 86).

For a user without Codex quota enabled, Allowances is an empty-state card ("No account connected" on Mac, `NativeDashboard.swift` lines 107 to 109) before they ever see screen time. That inverts the README table.

### Persistent development footers

Every Mac native section ends with:

```128:129:native/NativeDashboard.swift
                    Text("Provider account management and unified account-history sync are still being developed.")
                        .observatoryFont(.caption).foregroundStyle(.secondary)
```

Every Windows native section rebuild adds:

```109:109:native/windows/NativeDashboard.cs
            Label("Native migration preview. Provider sign-ins remain in their owning applications.");
```

Hypothesis: these captions train users to treat the whole dashboard as unfinished even when Activity and Tokens are valid. They also occupy vertical space at 200% Mac zoom.

### Workflows buried under Sources

Mac Sources puts a receipts summary, then a collapsed `DisclosureGroup("Execution details: receipts, benchmarks and tool requests")` (`NativeDashboard.swift` lines 240 to 256). Windows uses a **Show execution details** checkbox (`NativeDashboard.cs` around 228 to 232). Web uses `<details className="receipt-panel">`.

README presents Workflows as a peer view. Users looking for Agents from GUIDE will not find a matching rail item.

### Sources vs Settings source controls

Sidebar **Sources** is health tables. Editable toggles live in **Settings**. Same word, two jobs. Tray **Configure local collection** on Windows jumps to Settings (`Program.cs` `Configure()`). Mac popup gear does not.

## Compact chrome vs main window

### Mac panel

`ObservatoryPanel` shows freshness, optional allowance rings (up to two windows), host and period segments, Active time, Tokens, Voice, and `N of M sources read` (`Panel.swift` lines 13 to 99).

Issues:

1. Gear button accessibility label is "Observatory settings" (`Panel.swift` line 99) but the action is `showMenu()` (`main.swift` line 196). That opens the status-item context menu, not Settings.
2. Health dot is green when `counts.read == counts.total && !store.stale` (`Panel.swift` lines 76 to 78). It does not reflect `collectionPausedForPairing`, pairing maintenance, or stale quota inside an otherwise complete source count.
3. Empty snapshot copy: "Waiting for the first local snapshot. Sources refresh automatically while this Mac is awake." (`Panel.swift` lines 85 to 88). No spinner. No ActivityWatch-not-running diagnosis.
4. Host All copy: "Tokens include Mac, Windows and Ubuntu." (`Panel.swift` lines 71 to 73). Unverified combined tokens stay unavailable in the token stat. Hypothesis: users can read the footnote as if All-host tokens are present.

### Windows tray

Left click toggles the popup closed if it is already open (`Program.cs` lines 261 to 263). Tray tooltip is "updated Nm ago" from `collectedAt`, not per-source freshness (`RefreshStatus`, lines 343 to 348).

Usage popup refresh failures are swallowed in `finally` reload (`UsagePopup.cs` around line 133 per Windows audit). Hypothesis: a failed collection looks like a no-op.

Tray **Latest recorded totals** for All adds a verified-combined footnote (`Program.cs` line 360). The popup All host path does not. Hypothesis: empty All tokens in the popup lack that explanation.

### Opening the dashboard from compact UI

Both platforms close the popup when opening the main window. Mac Open Observatory targets allowances. Windows Open Observatory restores or creates the native form. Windows Configure from tray with no open dashboard creates a modal `ShowDialog()` instance (`Program.cs` lines 335 to 339). Hypothesis: that modal blocks the tray until dismissed and is a different window lifecycle than the ordinary main form.

## Empty, error, and loading states

### Strengths

- Empty activity/tokens: "No verified records. Missing data is unknown, not zero." (Mac `NativeDashboard.swift` lines 203 to 204, Windows `NativeDashboard.cs` line 125).
- Web fetch failure with prior data: "Could not reload. Showing the previous snapshot." (`app/page.tsx` lines 355 to 361).
- Stale snapshot banner when collector failed, hung, or older than ten minutes (`app/page.tsx` lines 352 to 354).
- Archive open failure explains rejection rules (Mac). Windows archive: "Saved history could not be read. No history was deleted."
- Quota graphs can describe missing `checkedAt` in accessible text (Windows tests).

### Gaps

| Surface | Loading | Error | Gap |
| --- | --- | --- | --- |
| Mac main Refresh | Button disabled when `store.refreshing` | No page-level collecting banner | User may not see that collection is running |
| Mac pairing pause | `collectionPausedForPairing` is not `@Published` (`Store.swift` line 17) | Refresh returns without UI | Silent dead collection |
| Web first paint | "Reading your local snapshot…" | Unconfigured Windows needs `setup.json` | `serve-local.mjs` does not serve `setup.json` (`docs/WEB-BOUNDARIES.md` line 8). Web-only users see "No snapshot available yet." |
| Windows native refresh | Button disabled while `busy` | MessageBox on failure | No inline progress |
| Setup wizard close | Closing incomplete setup leaves collection paused | Restart shows wizard again | No persistent in-dashboard "finish setup" callout if the user later opens a window without completing (Mac returns early from `showSetup` on launch) |

Web empty state for Windows setup (`app/page.tsx` lines 363 to 368) is accurate only when the native Windows bridge serves `setup.json`.

## Accessibility

Documented as unfinished (`docs/MAC.md` line 19, `docs/WINDOWS.md` line 41, `docs/UI-VERIFICATION.md` Still open, `docs/DESIGN.md` line 11).

Implemented well in places:

- Mac section headers use `.accessibilityAddTraits(.isHeader)`. Quota remaining vs reset coverage were split after a merged-element bug (`docs/UI-VERIFICATION.md` September 13).
- Windows custom charts set `AccessibleName` / `AccessibleDescription` (enforced in `UsagePopupTests` and dashboard tests).
- Web: `aria-label` on nav, period toggles, week bands. `aria-live="polite"` on dates. `prefers-reduced-motion` in `observatory.css`. Focus-visible outlines.

Gaps with file evidence:

1. SetupWizard Windows checkboxes have `Tag` and `Text` but no explicit `AccessibleName` (`SetupWizard.cs` lines 46 to 65).
2. Windows `Label()` sets `AccessibleName = value` to the full paragraph (`NativeDashboard.cs` lines 53 to 57). Long honesty copy becomes the accessible name.
3. Windows has no Command-1 through Command-6 equivalent. Mac View menu does (`docs/MAC.md` line 13, `native/main.swift` `makeMenu`).
4. Windows has no 75% to 200% text zoom. Mac applies it to native text and charts, not the popup, not setup/pairing dialogs (`docs/MAC.md` lines 15 to 19).
5. Quota archive keyboard: Tab historically failed to reach action buttons (`docs/UI-VERIFICATION.md` lines 9 to 11). Later Command-Return / Escape help. Full keyboard-only account/filter workflow remains unverified.
6. Dictation period `<select>` in web has a wrapping `<label>` without `htmlFor` / `id` (`app/dictation.tsx` line 27).
7. Activity day category track uses color segments plus `title` tooltips (`app/page.tsx` around 454 to 467). Hypothesis: proportion is not available as text for screen readers.
8. Sources web grid maps many non-ok statuses to "Unavailable" (`app/page.tsx` around 845 to 851). Token empty states are more specific.
9. Mac `MacUpdateGate.isBlocked` terminates with no window (`native/MacUpdateGate.swift`, `main.swift` lines 29 to 33). Contrast Windows, which can MessageBox "An installation or update is running" (`Program.cs` lines 132 to 137) unless `--background`.

Hypothesis (UI-VERIFICATION): complete every-control focus order and screen-reader review is still open, including populated views, both themes, and enlarged Mac layouts. Windows WebView2 interaction was not repeated for later native WinForms.

## Typography and charts

- Silent Inter Tight registration failure (`ObservatoryTheme`). Hypothesis: missing font falls back without user notice, mixing system and intended type.
- Mac 200% layout moves nav above content (`NativeDashboard.swift` lines 32 to 40). Inspected in empty-data previews per MAC.md. Populated tables at 200% in a 800-by-550 window remain a release gate.
- Quota archive sheet is a fixed 720-by-500 point sheet. Hypothesis: 200% dashboard scale inside that sheet will clip.
- Setup wizard is fixed 600-by-500 (Mac) / 620-by-520 (Windows) and ignores dashboard text scale.
- Web allowance charts are SVG plus `<progress>`. Spark / Bengal-fox buckets are filtered out (`app/allowances.tsx` around line 16), matching native `visibleQuotaWindows`.
- Native Windows graphs are owner-drawn. Tests cover accessible summaries. Visual contrast in light-on-dark for axis labels was not re-measured here.

## Mac vs Windows UI structure (summary)

| Concern | Mac | Windows |
| --- | --- | --- |
| Nav control | Sidebar buttons with SF Symbols, or horizontal popup above 125% zoom | Owner-drawn `ListBox`, 170px, no icons |
| Default device filter | `@State host = "Mac"` | `host = "Windows"` |
| Theme | User light/dark on main window. Popup always dark. | Main window always dark |
| Zoom | 75% to 200%, session-persistent | None |
| Section shortcuts | Command-1 to Command-6 | None |
| Agents | DisclosureGroup under Sources | Checkbox under Sources |
| Settings entry from compact UI | Gear opens full menu (mismatch) | Configure opens Settings editor (can be modal) |
| Footer | Product-direction unfinished copy | Native migration preview copy |
| Legacy | WebKit `--legacy-dashboard` | WebView2 `--legacy-dashboard` |

## Suggested Codex UI repairs

See `00-codex-handoff.md` for ordered backlog items. UI-specific acceptance themes:

1. Make compact-chrome settings affordances open Settings, or rename them so they do not say Settings when they open a menu.
2. Surface collection paused, collecting, and first-run incomplete states in both compact and main chrome.
3. Remove or gate development footers so they do not appear on every populated view in a release candidate.
4. Distinguish Sources health from Settings collection toggles in labels.
5. Close Windows accessibility gaps that Mac already has tests for (section keys, zoom, wizard names) or document them as accepted Windows-only limits in WINDOWS.md.
6. Keep missing-data empty states. Do not replace Unknown with zero to make charts look complete.
