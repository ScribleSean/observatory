# Private device sync

Implementation in progress. The September 9 decision is that both native apps show combined Mac and Windows data. Native collection can consume explicitly initialized private pairing state. No pairing has been installed into the live apps and no network peer exchange is enabled yet.

See [pairing maintenance](PAIRING-MAINTENANCE.md) for local revocation and the remaining repair limitations.

## Data boundaries

Each device continues collecting independently. Its own data remains available when the other device is disconnected. A received snapshot is a replacement for that device's previous snapshot, never an increment to add again.

Private peer state must be separate from the dashboard's `public/local` directory and excluded from packages, Git and browser routes. It will contain only the normalized activity intervals and keyed session comparison evidence needed to verify combined metrics, plus validated aggregate records. Raw session IDs, titles, prompts, transcripts, command arguments and credentials remain on their source device. Existing local readers sanitize those fields before export.

The two devices need one shared, randomly generated comparison salt for a pairing generation. The salt stays in private pairing configuration. A separate comparison ID identifies the generation without disclosing the salt. Rotating or revoking the pairing invalidates old comparison evidence. A comparison ID is not proof that a sender used the right salt. The producer, pairing configuration and authenticated transport must enforce that relationship.

## Implemented helpers

- `scripts/peer-inventory.mjs` checks explicit host ownership, bounded hashed-session inventories and the expected comparison generation. It rejects additional fields and incomplete evidence. Dashboard token totals omit the comparison keys.
- `scripts/peer-revision.mjs` checks pairing and device identifiers, a positive sequence, a content digest and collection time. Repeated deliveries are idempotent. Lower sequences cannot replace newer records. Conflicting equal sequences and regressing collection times fail closed. Data older than ten minutes is marked stale. Timestamps over five minutes ahead are rejected.
- `scripts/peer-payload.mjs` constructs allowlisted records, strictly validates received payloads and builds the same dashboard from either device's perspective. It keeps intervals and inventories out of dashboard JSON, preserves peer read times and withholds current combined totals when a peer is stale. These pure functions are not yet connected to native collection or transport.
- `scripts/peer-store.mjs` saves the validated payload and revision together in a local SQLite database at `private-sync/state.sqlite`, outside dashboard files. Separate local and peer slots prevent mutual overwrites. Transactions serialize writers, verify the content digest and allocate local publication sequences atomically. Duplicate and older transfers leave the current bytes unchanged. Linked paths and unexpected schemas are refused.
- `scripts/peer-directory.mjs` creates and verifies the private directory before storage access. On Windows, `scripts/private-sync-acl.ps1` creates protected inheritable permissions for the current account, SYSTEM and Administrators. It verifies the directory and immediate files, refusing unexpected owners, broad grants, reparse points and subdirectories. Existing unsafe permissions are rejected, not silently rewritten. This uses the Windows [DirectorySecurity API](https://learn.microsoft.com/en-us/dotnet/api/system.security.accesscontrol.directorysecurity?view=netframework-4.8.1). Administrators and processes running as the same user remain inside the trust boundary.
- `scripts/mac-snapshot.mjs` can produce a separate private peer export from the same source reads used for its local dashboard. No second Codex scan is needed. Missing comparison evidence withholds export without breaking local collection.
- `scripts/windows-dashboard.mjs` provides the corresponding Windows projection, including optional Ubuntu records.
- Both native collectors load saved pairing when present. `scripts/peer-collection.mjs` validates exact fields, host ownership, configured Codex sources and a 256-bit hex comparison salt. Collectors prepend that salt to the Python reader through stdin, never command-line arguments. Invalid pairing withholds export without disabling local collection. With no saved pairing, collection remains unpaired.
- `scripts/peer-pairing.mjs` generates complementary Mac and Windows configuration in memory, using random 256-bit identifiers and a shared salt. Initialization writes `private-sync/pairing.json` exclusively inside the verified private directory. Existing state cannot be overwritten implicitly. Reads are bounded and reject links, unsafe permissions, unexpected fields and inconsistent identities.
- `scripts/peer-setup.mjs` provides explicit Mac-initiated setup over the existing authenticated SSH route. It saves an inactive pending generation, requests Windows initialization through the fixed sibling `peer-setup-endpoint.mjs`, and activates locally only after acknowledgement. Retries preserve the original target, source scope and generation; the Windows endpoint refuses conflicting existing state. The Mac native dialog uses this command and its read-only status projection. Windows provides copyable installation details, with desktop visual review still pending. Repair/rotation remains unfinished. Partial file writes fail closed and require explicit repair rather than silent replacement.
- `scripts/peer-revocation.mjs` explicitly disables a local pairing with a persistent private marker. Pairing reads, private-store operations, outgoing collection and the exchange endpoint check the marker. Revocation retains pairing configuration, snapshots and sequence watermarks, refuses implicit reconnection, and also works when pairing configuration is malformed. It does not cancel bytes already sent or revoke the other device or its SSH access.
- `scripts/peer-finalize.mjs` connects normal native collection to the private store. It publishes the local revision, reads an already validated peer revision and creates the sanitized merged dashboard. Missing peers preserve standalone data. Storage or pairing failures do not stop local collection or reuse a failed peer projection. Secrets and inventories are never included in the dashboard or stdout status.
- `scripts/peer-exchange.mjs` is a bounded stdin/stdout endpoint for an authenticated SSH session. It verifies the local platform and saved pairing, requires a local export before accepting the peer record, and returns the local record. It does not open a network listener or implement authentication itself. The caller must verify the SSH host and account. Protocol extras, wrong device identities and missing local exports are rejected.
- `scripts/peer-transport.mjs` implements the optional Mac-initiated SSH caller. A private pairing may contain a validated Windows host alias and absolute executable, endpoint and runtime paths. The caller requires batch key authentication and strict host-key checking, disables password and interactive authentication, uses a 30-second bound, and sends records only through stdin. Mac collection publishes locally before attempting exchange, then merges either the received or previously cached peer record. Transport failure does not stop local publication. Windows merges the received Mac record on its next independent collection cycle.
- `scripts/read-settings-cache.py` provides a private file-granularity Codex cache for native Mac and Windows collection, paired or standalone. `private-codex/events.sqlite` retains only allowlisted numeric, model-setting and tool-identity events, with hashed call identifiers. Prompts, arguments, transcripts, raw session IDs and source filenames are not stored. Unchanged files are reused; changed files are reread in full, so edits and truncation invalidate their entries. The original per-run scan budget remains enforced. A cold cache may need multiple collection cycles and withholds complete totals while warming. Rolling cutoffs are recalculated from sanitized events. Individual entries are bounded to 16 MB and the database to 128 MiB. Ubuntu's reader still uses its existing uncached budget.
- `scripts/combine-tokens.mjs` accepts an explicit configured host set. Mac and Windows can combine without unconfigured Ubuntu. Configured missing sources still withhold totals. Shared sessions or parent relationships block summation.
- Existing activity combination unions overlapping intervals over the shared report window. It does not sum elapsed time across devices.

The digest is not a signature. Revision selection is not payload validation or transport authentication. Resetting a sequence requires an explicit repaired pairing generation, not silent acceptance of old records. SQLite owns transaction-lock recovery after a process crash. The database must reside on local disk, not an SMB or synchronized directory. Legacy development JSON state is refused instead of silently dropping its watermark. POSIX mode checks and Windows ACL checks are separate platform implementations. The tests do not simulate power loss or interrupted first-time database creation.

## Remaining implementation and verification

1. Verify paired native collection against live sources, including actual comparison evidence from the same read as aggregate records.
2. Complete Windows setup visual verification, explicit rotation and corrupt-state repair, and verify the Windows revocation controls and failure/retry presentation interactively. Verify browser routes cannot read private state.
3. Exercise an actual network disconnect/reconnect. Desktop-launched Mac exchange and key availability have passed a synthetic check. No reverse SSH access or new remote service is required.
4. Verify the implemented native merge in both running app dashboards, including per-device timestamps and stale-source visibility. Never imply that an offline cached peer is current.
5. Verify real disconnection, reconnection, repeated delivery, rotation, revocation and migration before replacing the working legacy collector or repackaging releases.

Thirty-two focused synthetic checks pass with the existing Mac arm64 and Windows x64 candidates' bundled Node 22.23.2 runtimes, including bidirectional projection, stale-source handling and private-field rejection. Windows checks used a separate source-only validation directory. These checks do not establish an end-to-end sync connection or change the shipped candidates.

Storage checks cover transaction contention, killed-writer rollback, isolated slots, linked-directory rejection, monotonic publication, timestamp regression and sequence exhaustion. Four independent publisher processes must allocate distinct consecutive sequences. All fixtures are temporary and synthetic.

The refactored Windows collector entry point also passes a temporary all-sources-disabled run on Windows. Its snapshot and status remain valid, and it creates no private peer state without pairing configuration. This is not a live-source sync test.

On September 9, a synthetic integration check used the existing Mac-initiated SSH connection with strict host-key checking. It initialized complementary temporary pairings, sent a Mac record through the Windows endpoint, accepted the returned Windows record on Mac, and verified both private stores. Repeating the exchange returned the same record and was accepted as a duplicate. Both temporary pairings and snapshots were removed afterward.

A subsequent integration check invoked the normal Mac collector entry point with the bundled runtime and a saved synthetic pairing containing transport configuration. Two collection cycles automatically exchanged records, confirmed by remote inspection of the increasing Mac sequence. After removing the synthetic remote runtime, another collection still published locally and retained the cached Windows snapshot's original timestamp. All synthetic pairing state was cleaned up. This tests an unavailable endpoint, not a real network interruption. The packaged GUI launch environment, live sources and pairing setup UI remain unverified or unimplemented.

A bounded live-source check first verified ActivityWatch collection and combined activity in both native collector projections. Native Windows Codex collection succeeded, but Mac Codex collection hit the saved-log scan budget. Combined tokens remained unverified, as required for a missing source.

After adding the private file cache, a repeated live check succeeded for both ActivityWatch and native Codex sources on both devices. The Mac's cold cache warmed across two budgeted collection cycles, after which both projections reported verified combined activity and token totals. A Windows timestamp-API mismatch found during testing was corrected without weakening the path, size or modification-time checks. Dictation and Ubuntu collection were not part of this paired check. All temporary pairing state, cache files and snapshots were removed; installed app settings were unchanged.

A later synthetic check launched the Mac app through Launch Services and triggered its native Refresh sources command. Independent private-store inspection confirmed that Windows received the Mac revision and Mac accepted the returned Windows snapshot. This verifies the current GUI launch environment, not a clean-machine setup or an actual network interruption. Both temporary pairings were removed.

The explicit setup CLI also completed against a disposable Windows runtime over the authenticated SSH route. A repeated invocation preserved the complementary pairings. Tests cover lost replies, conflicting remote state, changed retry targets, invalid acknowledgements, interrupted pending cleanup, concurrent attempts and revocation during setup. All synthetic setup state was removed after the live protocol check.

The Mac setup dialog subsequently completed the same authenticated setup against an isolated Windows fixture. Its saved target was prefilled and a repeated verification preserved the generation. Empty inputs, cancellation and an unavailable-peer message were checked interactively. Both temporary runtimes were removed. The existing installed apps were not paired or replaced by this check.
