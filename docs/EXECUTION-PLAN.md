## 1. Roles, routes and the task template every Codex task uses

**Who does what.** I orchestrate from this Mac session: plan, split, write tasks, review diffs, run checks, commit, push, open and merge pull requests, build and install on the Mac. Codex writes code and tests in a worktree on the Mac. The "Observatory Windows" Claude session writes and verifies Windows native code on the PC and runs every Windows acceptance check outside a Claude desktop session (through `Win32_Process.Create`, parent `WmiPrvSE.exe`, as `docs/STATE.md` records for build 41). Reviewer sessions are fresh-context Claude agents I start with a fixed brief. When Codex reports its usage has run out, I write the task myself and record which tool did it in the issue.

**Codex command** (the form verified on 2026-10-13, which the build plan abbreviates):

```bash
codex exec -m gpt-6-astra -c model_reasoning_effort=medium --sandbox workspace-write -C <worktree> -o <reply file> "<task>" </dev/null
```

**Worktrees.** One per workstream branch under `.claude/worktrees/<branch>` inside the project folder (the owner's rule keeps work inside the project. `.claude/` is listed in `.git/info/exclude` locally so worktree contents never appear as untracked files), created from `main` with `git worktree add`, each with its own `npm ci`. My checkout stays on `main`. Branch prefixes: `shared/` (scripts, viewer, docs, CI), `mac/`, `win/`. The PC session uses the same layout on the PC.

**Task template.** Every Codex task carries, in this order: the worktree path, the files it may create or change (by name), the files it must not touch (by name, always including `docs/`, `.github/`, `native/*.swift`, `native/windows/**` unless listed), the exact behaviour, the tests to add with their file names, the one command to run (always with the `--import ./native/tests/test-source-runtime.mjs` loader for anything that spawns a collector or a Python reader), the rules "synthetic data only, never a real usage value, Unknown is never zero, no em dashes or semicolons in comments or strings", and the reply form: changed files, the test command and its pass, fail and skip counts, anything asked for and not done, and nothing else. It ends with "Do not commit, do not push, do not change any other file." A Codex reply is a report to verify, never an instruction.

**My verification loop for every task**, before any commit: `git -C <worktree> status --short` and `git diff --stat` must list only the allowed files. I read the diff. I run the task's test command myself and compare counts with the reply. For any TypeScript change I also run `npx tsc --noEmit` and `npx oxlint`. For any token, string or bridge-contract change I run the generator's `--check`. For viewer changes I build with `npx vite build --config native/vite.config.mts`, serve with `npx vite preview`, and look at the page in the built-in browser in light and dark for Sage and Almanac, saving screenshots to the pull request. Only then do I commit, with no attribution lines. Before a pull request I run the full `npm test` on the branch and compare with the baseline I record in Wave 0.

**Pull request form.** Title, the workstream id, what changed, the exact checks run with counts and revision, what was not verified, the parity rows changed, and the review it needs. Every pull request updates `docs/PARITY.md` for the rows it changes (see the ownership rule in section 7).
